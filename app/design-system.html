Principles

The PRD asks for something clean, modern, minimal, and personal rather than corporate. These four decisions turn that into rules a component can be checked against.

Next action first

Every active application answers "what do I do now?" The one accent color in the system exists to answer it. If a screen has no marker on it, nothing is due, and that is a good state to be in.

Progress is shape, not color

Twelve statuses would need twelve colors, and that is how tools end up looking like enterprise HR software. Instead a ring fills as an application advances. Color is left for the few things that need it: due, overdue, rejected, error.

Quiet until it matters

Surfaces are separated by tone and hairlines. Shadows exist only for things that float: menus, dialogs, a card mid-drag. Numbers get the size, labels stay small and plain.

Personal, not corporate

A pine and paper palette with a slightly opinionated display face reads like a well-kept notebook rather than a dashboard from a vendor. Copy is plain, second-person, and never cheerful for its own sake.

Color

Neutrals carry about 90% of every screen. Pine is the single brand color and the primary action. The marker is a second, much rarer accent. Hex values below are light / dark; the swatches show the theme you are viewing.

Surfaces

Layer by tone: paper, then raised, with sunken for wells and columns. A hairline does the rest.

Ink and brand

Ink is a deep pine-black, not pure black. Buttons use pine. In dark mode pine flips to a pale sage so the primary button stays the loudest thing on screen.

The marker

Highlighter lime, always with ink text on top. It is used for the text of a next action that is due today or overdue, and for the "Due today" chip. Not for buttons, nav, headings, or decoration.

Save filters

Guardrail: at most two or three markers per screen region. If everything is highlighted, nothing is. Future actions stay plain text until their day arrives.

Signals

Every signal has a text-safe color and a tint for backgrounds. Success reuses pine, so a finished thing feels like part of the brand rather than a separate green.

Contrast

Measured against WCAG 2.2. Body text needs 4.5:1, control edges and meaningful graphics 3:1.

Typography

Two families with clearly different jobs. Bricolage Grotesque gives headings and big numbers a slightly humanist, opinionated voice. Instrument Sans stays out of the way for data-dense UI at 14px. Everything is sentence case. No all-caps labels, no letter-spaced eyebrows.

Families

Both are free on Google Fonts and Fontsource. Peso sign (₱) support should be checked in your build; the fallback stack covers it if a subset drops the glyph.

Stage ring

The signature element. Nine active stages fill the ring in eighths, so an application's progress is visible in a list of fifty without reading a word. Accepted fills completely and gets a marker-colored core. The three closed outcomes each have a distinct outline, so they are told apart by shape, not hue. The label always sits next to the ring.

All twelve statuses

Order matches the pipeline and the Kanban columns. Enum values come straight from the PRD status list.

    Accessibility and motion

    The PRD lists keyboard navigation, focus states, contrast, and screen-reader-friendly controls as requirements. They are part of the tokens here, not an afterthought.

    Rules

    • Never color alone. Status is ring shape plus a text label. Overdue is brick plus the words "Overdue 2 days". The ring SVG is aria-hidden because the label is right beside it.
    • Focus is always visible. A 2px pine outline with 2px offset on every interactive element, in both themes. Inputs use a 1px offset so the ring hugs the field.
    • Targets. 44px minimum hit area on touch, even where the drawn control is 30 or 36.
    • Kanban has a keyboard path. Every card exposes a "Move to" menu, so drag and drop is never the only way to change a status. Announce moves through a polite live region.
    • Motion answers actions. The marker sweep (500ms) plays once when a next action is set. New timeline rows fade in at 280ms. Dragged cards tilt. Nothing animates on page load. All of it collapses under prefers-reduced-motion.
    • Both themes are first-class. The theme follows the system and can be overridden; check both before shipping a component.

    Building it

    Two files carry the system. index.css holds every token in shadcn's variable names, so npx shadcn add button and friends come out on-brand with no edits. stage-ring.tsx holds the ring and the status map.

    shadcn adjustments

    Tokens do most of the work. These are the few component-level changes.

    ComponentChange
    ButtonDefault variant hover uses bg-primary-hover. Remove the default shadow. Add a danger variant with bg-destructive.
    Input, Select, TextareaBorder uses border-input (the 3:1 edge). Drop shadow-xs.
    CardRemove shadow-sm. Keep 1px border. Use rounded-xl for panels, rounded-lg for application cards.
    BadgeNot used for status. Status is ApplicationStatusBadge. Keep Badge for tags only.
    Dialog, Popover, ToastAdd shadow-float. Toast uses inverted ink with a text-marker Undo action.
    RechartsUse var(--chart-n). No legends where direct labels fit. Grid lines horizontal only.
